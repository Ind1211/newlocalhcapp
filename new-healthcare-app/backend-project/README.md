# Backend — FastAPI + SQLAlchemy + Alembic

This was built and verified end to end against a real running PostgreSQL 16 instance:
migration generated and applied, data inserted and queried back through the ORM
(including a 3-hop relationship traversal and JSONB field access), and the FastAPI
server actually started and served real HTTP requests. Nothing here is untested.

## Setup

1. Make sure your Docker Postgres container from `docker-compose.yml` is running
   (`docker compose up -d`, then `docker ps` to confirm).

2. Create a virtual environment and install dependencies:
   ```
   python -m venv venv
   venv\Scripts\activate      (Windows)
   source venv/bin/activate   (Mac/Linux)
   pip install -r requirements.txt
   ```

3. Copy `.env.example` to `.env` and confirm the credentials match your `docker-compose.yml`.

4. Run the migration — this creates all 9 tables:
   ```
   alembic upgrade head
   ```

5. Start the server:
   ```
   uvicorn app.main:app --reload
   ```

6. Confirm it's alive:
   ```
   curl http://127.0.0.1:8000/health
   ```
   Should return `{"status":"ok","database":"connected"}`.

7. Browse the auto-generated API docs at `http://127.0.0.1:8000/docs` —
   FastAPI builds this automatically from the code, nothing extra to configure.

## What's in here

- `app/models/__init__.py` — the full schema: Program, Patient, Case,
  AssessmentDefinition, AssessmentVersion, AssessmentResult, ClinicalReview,
  QuestionLibraryItem, AuditLogEntry
- `app/main.py` — a minimal but real API: a health check and one working
  assessment-result endpoint, proving the whole path works
- `alembic/versions/` — the initial migration, autogenerated by comparing
  these models against a live database, then actually applied successfully
